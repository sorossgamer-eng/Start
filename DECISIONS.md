## 2026-11-25 — Главный стиль сайта

**Решили:** главный стиль — тёмно-синий фон (`#050d15` → `#0d1e30`) и оранжевый акцент, как в `CLAUDE.md`. Описание стиля в `project.md` приведено к нему.

**Почему:** в `project.md` был описан другой стиль (почти чёрный фон, розовый и золотой акценты), и было непонятно, какой из двух главный.

## 2026-11-25 — Порядок в репозитории

**Решили:** HTML-страницы оставить в корне, документы собрать в `docs/`, старые версии убрать в `archive/`, настройки VS Code перенести в `.vscode/`. Удалили дубликаты: папки `Projects/` и `promt-dly-proekta/`, сломанный `my-first-project.code-workspace`.

**Почему:** в корне было трудно найти нужное, часть файлов лежала в двух-трёх копиях.

**Важно:** страницы в корне и `tg-app/` не перемещать. По их адресам открывается сайт на GitHub Pages и Mini App в Telegram-боте.

## 2026-11-25 — raytsystem не встраиваем в проект

**Решили:** не устанавливать агентную систему raytsystem (`romarayt/raytsystem-public-os`) в этот репозиторий. Вместо неё ведём `README.md` (карта проекта) и этот файл (решения).

**Почему:** это отдельное приложение на Python (около 1000 файлов), рассчитанное на запуск на своём компьютере. Под Windows работает только через WSL 2, автор помечает его как раннюю версию. Для проекта из HTML-страниц это слишком тяжело.

**Если понадобится:** ставить на компьютер отдельно от проекта.

## 2026-11-25 — Шаблоны сайтов в `vibe-sites/`

**Решили:** сохранить в репозитории пять шаблонов из плагина `vibe-shablony-vip` (каталог `vibe-bonus/shablony-vip`).

**Почему:** в облачной сессии файлы временные, а в репозитории они хранятся постоянно.

**Ограничения:** в шаблонах демонстрационные данные (компании, телефоны, цены, отзывы). У шаблонов свой дизайн, правила оформления из `CLAUDE.md` на них не распространяются.

## Хостинг и инфраструктура

**Решили:** фронтенд публикуется через GitHub Pages (обновляется сам после `git push` в `main`). Бэкенд Mini App работает на VPS Beget, база данных в Supabase.

**Подробности:** `docs/DEPLOYMENT.md`, `docs/BACKEND-PLAN.md`.

## Правила вёрстки

**Решили:** каждая страница — отдельный HTML-файл, стили внутри `<style>`, без внешних библиотек.

**Почему:** страницы открываются двойным щелчком и на GitHub Pages без сборки и установки.

**Дизайн:** тёмно-синий фон (`#050d15` → `#0d1e30`), светлый текст, оранжевый акцент, адаптивная вёрстка.
